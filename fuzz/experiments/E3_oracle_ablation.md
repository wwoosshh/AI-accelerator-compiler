- 데이터: 패치 없는 torch 2.14.0+cu130 에서 나온 불일치 사례 151건 (`results/smoke_aot`, `smoke_ind`, `A_aot_cpu`, `B_ind_cuda`)
- 방법: 각 사례의 diff 경로를 분류. `callN.out[...]` 이 있으면 "반환값 비교로 검출", `callN.argK` 만 있으면 "변이된 입력 상태 비교로만 검출", `probe.*` 만 있으면 "별칭 프로브로만 검출", 모든 diff 가 `call1`/`probe.call1` 이면 "2회차 호출로만 검출".

## 해석

1. **출력값만 비교하는 오라클(NNSmith, NeuRI, TorchProbe, WhiteFox 의 기본 오라클)은 151건 중 46건(30%)을 놓친다.** 22건은 함수가 반환하지 않는 입력 텐서가 조용히 손상된 경우(A 의 `f_mut` 형태: `v = x.unfold(1,1,5); v.add_(v)` 만 하고 `x` 를 반환하지 않음)라 입력의 최종 상태를 비교해야만 보인다. 24건은 반환 시점 값은 같고 별칭 관계만 다른 경우라 별칭 프로브가 필요하다.
2. **별칭 프로브가 유일한 검출 수단인 버그가 실제 존재한다.** 알려진 #197893(`x + 0` 이 입력 자체를 반환) 15건 전부와 B 계열 6건이 그렇다. #197893 은 2026-09-21 에 다른 신고자가 값 손상 형태로 보고했지만, 우리 프로브는 손상이 일어나기 전의 별칭 상태에서 잡는다.
3. **2회차 호출 오라클은 이번 데이터에서 단독 검출이 없었다.** 가드·캐시 버그(실증 연구 분류의 4.3%)가 우리 생성기의 프로그램 공간에 적게 포함된다는 뜻이며, `k` 외에 형상·dtype·모듈 상태 변화를 2회차에 넣는 확장이 필요하다는 근거가 된다.
4. 반환값 비교만으로도 70% 는 잡히므로, 우리 도구의 차이는 오라클 하나가 아니라 **생성기(별칭·in-place 프로그램 공간) + 오라클(입력 상태·별칭)** 의 결합에서 온다. E1/E2 가 생성기 쪽 기여를 분리해 보여준다.

## 한계

- 사례 수는 "발견된 불일치 프로그램" 이지 "고유 버그" 가 아니다. 계열별 고유 버그 수는 A 1, B 1, D 1, H 3, I 1, K 1 이다.
- 동적 형상·별칭 입력 옵션이 켜진 프로그램의 비율(각 35%, 30%)이 검출 분포에 영향을 준다.
